# Документ требований: Улучшения SDK

## Введение

Данный документ описывает требования к улучшению существующего Go SDK для EasyP API Service. SDK расположен в директории `sdk/` и предоставляет клиентский доступ к gRPC-сервису генерации кода. Текущая реализация содержит баг компиляции (неиспользуемая переменная `ctx` в `NewClient`), а также не имеет механизмов повторных попыток, таймаутов, фильтрации плагинов, перехватчиков и проверки состояния соединения.

## Глоссарий

- **SDK_Client**: Go-клиент (`Client` struct в `sdk/client.go`), обеспечивающий взаимодействие с EasyP API Service по gRPC
- **EasyP_Service**: gRPC-сервис генерации кода, определённый в `api/generator/v1/generator.proto` (сервис `ServiceAPI`)
- **Retry_Policy**: Политика повторных попыток, определяющая количество попыток, интервалы и стратегию backoff
- **Interceptor**: gRPC-перехватчик (unary/stream), выполняющий логику до и после вызова RPC
- **Health_Check**: Механизм проверки доступности и состояния gRPC-соединения
- **Plugin_Filter**: Структура фильтрации плагинов по полям group, name, version (определена в `internal/core/domain.go`)
- **Option**: Функциональная опция для конфигурации SDK_Client (паттерн functional options)

## Требования

### Требование 1: Исправление бага компиляции в NewClient

**User Story:** Как разработчик, я хочу, чтобы SDK компилировался без ошибок, чтобы я мог использовать его в своих проектах.

#### Критерии приёмки

1. THE SDK_Client SHALL компилироваться без ошибок и предупреждений при вызове `go build ./sdk/...`
2. WHEN функция `NewClient` вызывается с валидным адресом, THE SDK_Client SHALL создавать gRPC-соединение и возвращать инициализированный экземпляр Client без ошибок компиляции
3. THE SDK_Client SHALL удалить неиспользуемую переменную `ctx` из функции `NewClient` или использовать её по назначению

### Требование 2: Повторные попытки с экспоненциальным backoff

**User Story:** Как разработчик, я хочу, чтобы SDK автоматически повторял неудачные запросы с экспоненциальным backoff, чтобы временные сбои сети не приводили к ошибкам в моём приложении.

#### Критерии приёмки

1. THE SDK_Client SHALL поддерживать настройку Retry_Policy через Option
2. WHEN запрос к EasyP_Service завершается с транзиентной ошибкой (коды `UNAVAILABLE`, `DEADLINE_EXCEEDED`, `RESOURCE_EXHAUSTED`), THE SDK_Client SHALL автоматически повторить запрос в соответствии с настроенной Retry_Policy
3. THE SDK_Client SHALL использовать экспоненциальный backoff между повторными попытками с добавлением случайного jitter
4. THE SDK_Client SHALL по умолчанию выполнять не более 3 повторных попыток с начальным интервалом 100 мс
5. WHEN количество повторных попыток исчерпано, THE SDK_Client SHALL вернуть последнюю полученную ошибку
6. WHEN контекст запроса отменён во время ожидания повторной попытки, THE SDK_Client SHALL немедленно прекратить повторные попытки и вернуть ошибку контекста

### Требование 3: Таймауты по умолчанию для запросов

**User Story:** Как разработчик, я хочу, чтобы SDK устанавливал разумные таймауты по умолчанию для всех запросов, чтобы мои приложения не зависали при недоступности сервиса.

#### Критерии приёмки

1. THE SDK_Client SHALL устанавливать таймаут по умолчанию 30 секунд для вызовов `GenerateCode`
2. THE SDK_Client SHALL устанавливать таймаут по умолчанию 10 секунд для вызовов `ListPlugins`
3. THE SDK_Client SHALL поддерживать настройку таймаутов через Option (опции `WithGenerateCodeTimeout` и `WithListPluginsTimeout`)
4. WHEN пользователь передаёт контекст с собственным дедлайном, THE SDK_Client SHALL использовать меньший из двух дедлайнов (пользовательский или дефолтный)
5. WHEN таймаут запроса истекает, THE SDK_Client SHALL вернуть ошибку с кодом `DEADLINE_EXCEEDED`

### Требование 4: Фильтрация плагинов в ListPlugins

**User Story:** Как разработчик, я хочу фильтровать список плагинов по группе, имени и версии, чтобы быстро находить нужные плагины.

#### Критерии приёмки

1. THE SDK_Client SHALL принимать параметр Plugin_Filter в методе `ListPlugins`
2. WHEN Plugin_Filter содержит непустое поле `Group`, THE SDK_Client SHALL передавать значение фильтра в запрос к EasyP_Service
3. WHEN Plugin_Filter содержит непустое поле `Name`, THE SDK_Client SHALL передавать значение фильтра в запрос к EasyP_Service
4. WHEN Plugin_Filter содержит непустое поле `Version`, THE SDK_Client SHALL передавать значение фильтра в запрос к EasyP_Service
5. WHEN Plugin_Filter пуст (все поля пустые), THE SDK_Client SHALL возвращать полный список плагинов без фильтрации
6. THE SDK_Client SHALL обеспечить обратную совместимость, предоставив метод `ListPlugins` без фильтра или с фильтром по умолчанию (пустой фильтр)

### Требование 5: Перехватчики (Interceptors)

**User Story:** Как разработчик, я хочу подключать перехватчики для логирования и метрик, чтобы отслеживать работу SDK в продакшене.

#### Критерии приёмки

1. THE SDK_Client SHALL поддерживать добавление пользовательских unary gRPC Interceptor через Option
2. THE SDK_Client SHALL поддерживать добавление нескольких Interceptor, которые выполняются в порядке добавления (цепочка)
3. THE SDK_Client SHALL предоставлять встроенный Interceptor для логирования, записывающий метод RPC, длительность вызова и статус ответа
4. THE SDK_Client SHALL предоставлять встроенный Interceptor для метрик, собирающий количество вызовов, длительность и коды ответов
5. WHEN Interceptor добавлен через Option, THE SDK_Client SHALL применять Interceptor ко всем исходящим gRPC-вызовам

### Требование 6: Проверка состояния соединения и переподключение

**User Story:** Как разработчик, я хочу, чтобы SDK автоматически проверял состояние gRPC-соединения и переподключался при разрыве, чтобы обеспечить надёжную работу в долгоживущих приложениях.

#### Критерии приёмки

1. THE SDK_Client SHALL поддерживать включение периодической проверки состояния gRPC-соединения через Option
2. WHEN проверка состояния соединения включена, THE SDK_Client SHALL выполнять проверку с настраиваемым интервалом (по умолчанию 30 секунд)
3. WHEN gRPC-соединение переходит в состояние `TRANSIENT_FAILURE` или `SHUTDOWN`, THE SDK_Client SHALL инициировать переподключение
4. THE SDK_Client SHALL использовать встроенный механизм gRPC keepalive для поддержания активного соединения
5. THE SDK_Client SHALL поддерживать настройку параметров keepalive через Option (интервал ping, таймаут ping)
6. WHEN переподключение не удаётся после настраиваемого количества попыток, THE SDK_Client SHALL вернуть ошибку при следующем вызове метода
