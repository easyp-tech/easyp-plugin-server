## T-3: CODE — Реализовать функцию `Up()` с goose + advisory lock

*_Requirements: REQ-2.1, REQ-2.2, REQ-2.3, REQ-2.4, REQ-5.1, REQ-5.2_*
*_Preservation: CP-1, CP-4, CP-5, CP-6, CP-7, CP-8, CP-10_*
*_Complexity: standard_*

GOAL: Реализовать миграционную функцию с goose API, embed.FS и PostgreSQL advisory lock.

1. Добавить зависимость `github.com/pressly/goose/v3` — выполнить `go get github.com/pressly/goose/v3`.

2. Создать файл `internal/database/goosemigrate/goosemigrate.go`:
   - `//go:embed migrations/*.sql` для `embed.FS`
   - Функция `Up(ctx context.Context, dsn string) error`:
     - `sql.Open("postgres", dsn)`
     - `db.PingContext(ctx)` — проверка доступности
     - Создать `goose.Provider` с:
       - `goose.WithStore(goose.NewPostgresStore())` — используется стандартная таблица `goose_db_version`
       - `goose.WithSessionLocker(goose.NewPostgresSessionLocker())` — advisory lock
     - Альтернативно (если Provider API сложнее) использовать функциональный API:
       - `goose.SetBaseFS(migrationsFS)`
       - `goose.SetDialect("postgres")`
       - `goose.Up(db, "migrations")`
     - `defer db.Close()`
     - При ошибке — return `fmt.Errorf("goosemigrate.Up: %w", err)`
   - IMPORTANT: проверить актуальный API goose v3 — Provider API vs functional API. Использовать то, что стабильнее.

3. Запустить `go build ./internal/database/goosemigrate/` — должно скомпилироваться.

4. Запустить `go vet ./internal/database/goosemigrate/` — должно пройти.
