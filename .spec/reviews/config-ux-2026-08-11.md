## 1. Что делает изменение

Задача — **единый и предсказуемый путь сборки конфига** для server, `plugins push` и deploy-оверлеев, вместо двух несовместимых веток.

### Было

| Путь | Поведение |
|------|-----------|
| `--cfg file.yml` | YAML decode → `Validate`. Envconfig **не** применялся; секреты (`LICENSE_*`, `REGISTRY_S3_*`) — только через ad-hoc resolvers в CLI |
| без `--cfg` | только `envconfig.Process` |
| defaults в struct tags | не работали на YAML-пути → zero values, late failures, telemetry на `localhost` с вечными retry |

### Стало

```
YAML (если --cfg) → env overlay (DefaultOverwrite + empty-is-unset) → tag defaults → Validate
```

Ключевые механики:

- **`LoadAndValidate(ctx, path)`** / **`ApplyEnv`** — один `applyEnv` для file-path и env-only
- **`emptyIsUnset`** — compose-стиль `"${VAR:-}"` (set but empty) **не затирает** YAML
- **`DefaultOverwrite: true`** — реальный env бьёт значения из файла (секреты не в git)
- Жёсткая **валидация раньше**: DSN, metric/health/mcp ports, timeouts, `max_retries ≥ 0`, `cleanup_interval > 0`, audit pre_create ≤ retention
- Telemetry: **пустой endpoint = нет exporter** (defaults на localhost убраны)
- Deploy: tier-конфиги без write-token digests; pinned `172.28.0.0/16` + `trusted_proxies`; env examples выровнены

## 2. Обзор по областям

### Config core (`internal/config`)

- Единый load path, cap 1 MiB, warnings по unknown YAML fields
- `export_test.go` + объёмный `load_test.go` (precedence, empty-is-unset, shipped configs, S3 half-credentials)
- `Validate` расширен осмысленными fail-fast правилами

### CLI (`cmd/easyp-svc`)

- `start.loadConfig` — оба пути сходятся
- Убраны ручные license/S3 resolvers
- `plugins push` тоже через `LoadAndValidate` (консистентность S3/store, см. Issue 3)
- Unknown fields → `log.Warn` **до** hard error (хороший UX при опечатке в ключе)

### Deploy / env

- `.env.example` / `.env.dev.example`: `AUTH_WRITE_TOKENS`, `DB_POSTGRES_DSN`, `TELEMETRY_*`, S3
- Tier YAML: `write_tokens: []`, пустая telemetry
- Compose: bare `OTEL_*` убраны; передаются `TELEMETRY_*`
- Helm: комментарий «empty OTLP = no exporter»

### Rate limiter / pool / telemetry

- Rate limiter: `setDefault()` + cleanup test — защита от `time.NewTicker` panic после «успешного» start
- Pool: `MaxRetries == 0` больше **не** подменяется на 2 (zero = один attempt)
- Telemetry: skip exporter/profiler при пустых endpoints

### Docs

- README: precedence, empty-env, `TELEMETRY_` prefix quirk

## 3. Breaking / migration notes

| Изменение | Влияние |
|-----------|---------|
| Env всегда overlays YAML при `--cfg` | Env-переменные должны быть осознанными; empty compose injection безопасен |
| Нет defaults на telemetry endpoints | Кто ждал implicit `localhost:4317` — получит «off» (это правильно) |
| Tier: `auth.write_tokens: []`, empty telemetry | Public/dev deny writes без `AUTH_WRITE_TOKENS`; observability только через env |
| `db.postgres` обязателен | Пустой DSN больше не уходит в libpq env |
| Metric/health/mcp ports обязательны | Неполные конфиги падают раньше |
| `max_retries: 0` в pool | Pool больше не форсит 2 retries (но YAML zero ломается — Issue 1) |
| Ad-hoc license/S3 resolvers в CLI убраны | Всё через unified `ApplyEnv` |

## 4. Issues

### Issue 1 — bug (blocker)

- **File:** `internal/config/config.go` (`applyEnv` / envconfig, ~line 632)
- **Status:** open

После YAML decode envconfig с `DefaultOverwrite: true` **перезаписывает explicit YAML zero** tag-default'ом: go-envconfig сохраняет pre-set field только если он **non-zero** и env key not found.

| Поле | YAML zero (документированный смысл) | Что получится |
|------|-------------------------------------|---------------|
| `worker_pool.max_retries: 0` | один attempt, без retries | → `2` |
| `registry.cache_max_bytes: 0` | disable eviction | → 20 GiB default |
| `rate_limit.max_concurrent_per_ip: 0` | disable check | → `2` |
| `audit.retention_months: 0` | keep forever | → `12` |

Env-path работает (`WORKER_POOL_MAX_RETRIES=0` — non-empty, found) → **два пути расходятся**. Тесты покрывают только non-zero string override.

**Suggestion (варианты фикса):**

1. Убрать `default=` у полей, где zero first-class; defaults только в shipped YAML/docs.
2. Pointers / sentinel decoder.
3. Custom layer «omitted vs explicit zero» (YAML null vs `0`).

Обязателен table test: YAML `max_retries: 0` (и остальные zeros) выживает `LoadAndValidate` с empty env.

---

### Issue 2 — suggestion

- **File:** `deploy/config/config.local.yml` (~line 32)
- **Status:** open

Tier-конфиги правильно blank telemetry; `config.local.yml` всё ещё hardcode `localhost:4317` / Pyroscope — local без Alloy снова строит exporters и retry spam, который PR как раз убирал.

**Suggestion:** empty endpoints + `TELEMETRY_*` когда observability stack up (как tier configs / `.env.dev.example`).

---

### Issue 3 — suggestion

- **File:** `cmd/easyp-svc/push.go` (~line 86)
- **Status:** open

`plugins push --cfg` теперь проходит **полный** `Validate` (DSN, все ports, …). Минимальный YAML только с `registry.s3` — fail, хотя push'у нужен только S3.

**Suggestion:** документировать «нужен full service config» **или** lighter path / push-specific validation.

---

### Issue 4 — nit

- **File:** `internal/config/config.go` (~line 528, godoc `LoadAndValidate`)
- **Status:** open

Godoc: «increasing precedence» читается как defaults > env. Фактически: **env > file > tag default**. Claim «default не перезаписывает file» неверен для zeros (Issue 1).

**Suggestion:** перефразировать: «precedence: environment > file > tag default» и отметить zero-value caveat до фикса Issue 1.

---

### Issue 5 — nit

- **File:** `README.md` (~line 334)
- **Status:** open

`DB_MIGRATE_DIR` / `db.migrate_dir` — **ghost keys**, в `config.Config` нет. Рядом расширена env-документация → список выглядит authoritative.

**Suggestion:** убрать migrate_dir строки или заменить на актуальный механизм миграций.

## 5. Оценка Config UX

### Что реально улучшилось

- Одна история резолва для `--cfg` и env-only; README объясняет order и empty-env
- Секреты вне git: overlay `LICENSE_*`, `REGISTRY_S3_*`, `AUTH_WRITE_TOKENS`, `DB_POSTGRES_DSN`
- `emptyIsUnset` делает compose-idiom безопасным
- Public tier без published write-token digests (security + UX default deny)
- Trusted proxies + pinned subnet — rate-limit/audit identity за Traefik
- Fail-fast вместо late panic / wrong DB / empty success
- Telemetry off expressible; docs про `TELEMETRY_` vs bare OTel
- Unknown YAML → startup warnings
- Server и `plugins push` не разъезжаются по S3

### Что ещё rough

- **YAML zero vs env zero** (Issue 1) — главный UX footgun поверх аккуратного дизайна
- Нельзя blank non-empty YAML value из env (задокументированный tradeoff)
- Длинное имя `TELEMETRY_OTEL_EXPORTER_OTLP_ENDPOINT`
- `EASYP_TOKEN` (client) vs `AUTH_WRITE_TOKENS` (server digests) — в `.env.example` уже объяснено; держать на виду

### Consistency matrix

| Concern | Code | YAML | Env examples | Compose |
|---------|------|------|--------------|---------|
| License | `LICENSE_*` | empty / `{}` | ok | passed |
| Write tokens | `AUTH_WRITE_TOKENS` | tier `[]` | ok | both stacks |
| Telemetry | `TELEMETRY_*`, no default | tier empty; main alloy; **local localhost** | ok | ok |
| S3 | `REGISTRY_S3_*` | secrets often empty | ok | passed |
| Trusted proxies | tags | `172.28.0.0/16` | — | IPAM pinned |
| DSN | required | shipped | ok | override |

Остаточные mismatch: local telemetry (Issue 2), README migrate_dir (Issue 5).

## 9. Вердикт

### **Request changes**

**Blocker**

- Issue 1: explicit YAML zeros перезаписываются envconfig `default=` — ломает documented semantics для retries / cache / concurrency / retention. Пока не fixed (или deliberate escape hatch + docs + tests) layering нельзя считать завершённым.

**Итог одной фразой**

Архитектура резолва конфига и операторский UX заметно сильнее (один путь, секреты, fail-fast, telemetry off, deploy alignment), но **семантика zero values на YAML-пути — регрессия correctness**, из‑за которой `Request changes` оправдан.
