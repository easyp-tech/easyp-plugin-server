## Вердикт

Разворачивать «как в README» можно. Понять и предсказать конфигурацию с первого раза — нельзя.

Слои и `easyp-svc config print` уже сделаны хорошо. Ломает вход: три словаря имён, молчаливые опечатки и принцип «в файле только отличия», из‑за которого схема живёт в бинаре, а не у оператора.

Каждая находка ниже помечена, чем подтверждена: командой, экспериментом, чтением кода или предположением.

## Находки

### 1. Опечатка в ключе — это успешная конфигурация

**Кому боком:** любому, кто копирует Helm `cacheMaxBytes` в YAML или промахивается по клавише. Сервис стартует на дефолтах и молчит, будто его послушали.

**Чем подтверждено.** Эксперимент: файл с `server.porrt.grpc: 8888` и `registry.cacheMaxBytes: 1` плюс валидный DSN.

```
warning: unrecognised field, ignored: ... field porrt ...
warning: ... field cacheMaxBytes not found in type config.RegistryConfig
/tmp/easyp_cfg_typo_ok.yml is valid.
54 settings: 1 from the file ...
exit: 0
```

`config print --origin` показывает `grpc: "23410" # default`. Заданного порта нет нигде. `validate` зелёный.

Тот же класс: `server.port.grpc: not-a-number` — **valid**, потому что порты в структуре — строки, не числа. Падение будет на `listen`, не на конфигурации.

Helm пишет camelCase (`cacheMaxBytes`, `otlpEndpoint`, `trustedProxies`), YAML — snake_case. Это не вкусовщина: это генератор тех самых опечаток, которые загрузчик проглатывает.

**Дополнение (проверено запуском после карты загрузчика).** `config print` предупреждения об unknown keys **выбрасывает**: в `resolveForPrint` (`cmd/easyp-svc/config.go`) второй возврат `LoadAndValidateWithOrigins` — `_`. На том же файле с `porrt` stderr у `print` пустой; `--changed --origin` печатает только DSN из файла. Инструмент, который должен ответить «что реально применится», скрывает то, что не применилось. Комментарий в `validate` говорит, что unknown field — «самый вероятный explainer сбоя валидации»; unknown keys валидацию не валят.

`plugins push` те же warning тоже отбрасывает.

**Что делать:** неизвестный ключ должен валить `validate` и старт (exit ≠ 0). `print` обязан показывать те же warning, что `validate`. Предупреждение, которое CI и человек могут игнорировать, — это не проверка.

### 2. Три словаря плюс четвёртый, которого уже нет

Одна настройка — три имени, и ни одно не угадывается из другого.

| Смысл | YAML | env | Helm values |
|---|---|---|---|
| OTLP | `telemetry.otlp_endpoint` | `TELEMETRY_OTEL_EXPORTER_OTLP_ENDPOINT` | `config.telemetry.otlpEndpoint` |
| потолок каталога плагинов на диске | `registry.cache_max_bytes` | `REGISTRY_CACHE_MAX_BYTES` | `config.registry.cacheMaxBytes` |
| метрики | `server.port.metric` | `SERVER_PORT_METRIC` | `ports.metrics` (множ. число) |
| ключи лицензии | `license.public_keys` | `LICENSE_PUBLIC_KEYS` (`kid:hex`) | `config.license.publicKeys` (map) |
| кто имеет право писать | `auth.write_tokens` | `AUTH_WRITE_TOKENS` (`name=hex`) | только секрет, не values |

**Чем подтверждено.** Эксперимент:

- `OTEL_EXPORTER_OTLP_ENDPOINT=localhost:4317` → в `--changed` телеметрии нет.
- `TELEMETRY_OTEL_EXPORTER_OTLP_ENDPOINT=localhost:4317` → значение встаёт, origin `env`.
- `AUTH_WRITE_TOKENS='local-dev:…'` (двоеточие, как у ключей лицензии) → ошибка парсера. Нужно `name=hex`.
- `LICENSE_PUBLIC_KEYS='kid1:deadbeef'` — наоборот, только двоеточие.

Это не «self-hosted так устроен». Префикс секции в имени OTLP — следствие `env:", prefix=TELEMETRY_"` плюс поле, названное как у OpenTelemetry. Стандартное имя SDK **намеренно** не читается; это написано в README и в chart README. Но человек, который настраивал коллектор десять раз, поставит `OTEL_EXPORTER_OTLP_ENDPOINT` и получит сервис без трейсов и без ошибки.

Публичные доки (`docs-fumadocs/.../api-service/overview.md`) до сих пор учат `EASYP_SERVICE_HOST`, `EASYP_SERVICE_GRPC_PORT`, `EASYP_SERVICE_DB_*`. Сервис этого не читает. Человек с сайта настроит другой продукт.

Helm README утверждает, что public keys «рендерятся в `LICENSE_PUBLIC_KEYS`». Это уже не так: ConfigMap пишет YAML `license.public_keys`.

**Что делать:** либо одно каноническое имя на настройку (YAML = env без префиксной магии), либо таблица «все имена» в README рядом с Quick Start. Сейчас таблица есть только у того, кто уже открыл `config.go`.

### 3. «В файле только отличия» — правильная идея с уже оплаченным счётом

Принцип записан в шапке каждого `deploy/config/*.yml` и в коммите `d02cb8a` (соавтор — агент): повторять дефолты нельзя, потому что `max_retries: 3` в compose и `2` в чарте жили месяцами.

Это работает **только вместе с** `config print --origin` и только на бинаре, который умеет `mergeFileValues`.

**Живой контрпример, не комментарий.** Локальные `easyp-api-community` / `easyp-api-enterprise` на момент аудита были в Restarting:

```
config validation: db.driver is required
```

Образ `ghcr.io/easyp-tech/service:latest` от 7 августа. В текущем YAML секция `db:` есть, ключа `driver` нет (дефолт `postgres` в теге). Текущий бинарь на том же файле:

```
deploy/config/config.community.dev.yml is valid.
54 settings: 14 from the file, 0 from the environment, 40 left at defaults.
```

`db.driver` в `--changed` не появляется — он с дефолта. Старый загрузчик при частичном `db:` обнуляет соседние поля. Оператор видит требование поля, которого нет ни в файле, ни в README.

Вторая уже случившаяся цена принципа — та, о которой предупреждает сам `config.enterprise.dev.yml`: дефолт `cache_max_bytes` = 20 GiB на диске 14 GB. Пока значение не выписали явно (2 GiB в *dev*-файлах), eviction не начинался, диск кончался раньше. В **`config.yml` основного compose этого ключа по-прежнему нет** — снова 20 GiB из бинаря. Алерт в `deploy/observability/mimir/rules/anonymous/easyp.yaml` всё ещё говорит, что порог «совпадает с `config.yml`», хотя в `config.yml` ключа нет.

Helm принцип **отрицает**: `values.yaml` сознательно повторяет все дефолты, чтобы `helm show values` был справочником. Два входа — два разных договора с оператором. Helm всегда пишет `cache_max_bytes: 21474836480` в файл, поэтому origin — `file`, даже когда значение совпадает с бинарем.

**Что принцип даёт:** видно, что *этот* деплой меняет.
**Чего стоит:** схема больше не лежит в файле; «пусто» = «дефолт бинаря, который вы не видели»; смена образа и файла должна быть атомарной.

**Что делать:** не откатывать принцип в Helm (там полный values — правильный интерфейс). Для compose — либо генерировать «полный resolved» рядом, либо в README шаг 0: `config print --cfg … --origin`. И не монтировать новые yaml в старый образ без той же проверки.

### 4. README — главный вход — расходится с продуктом

Человек, который не читает Go, идёт сюда. Там:

| README говорит | На самом деле |
|---|---|
| Quick Start: `./register-plugins.sh localhost:8080` | файла нет; регистрация уже внутри `task run-local` / `task register-plugins` |
| env-пример `SERVER_PORT_GRPC=8080` | дефолт бинаря **23410–23413**; 8080 ставят только файлы и чарт. Chart README это знает, README сервиса — нет |
| пример YAML `worker_pool.max_retries: 3` | дефолт и чарт = 2; ровно тот дрейф, ради которого урезали файлы |
| приоритет нумерован «1. файл, 2. env перекрывает» | это env > file > default, но новичок читает список сверху |
| про `config print` / `validate` | **ни слова**. Есть в шапках yaml, в `.env.example` и в chart README |
| prerequisite: grpcurl | для документированного пути не нужен |
| `AGENTS.md`: «CLI flags > env > YAML», ссылка на `docs/configuration.md` | файла нет; из флагов на поля конфига влияет только `--cfg`. `--log_level` — отдельный канал, в YAML его нет |

**Чем подтверждено:** чтение README + `ls register-plugins.sh` + `rg 'config print' README.md` (пусто) + `config print` без файла (порты 23410).

Пока README такой, хорошие инструменты не существуют для целевой аудитории.

### 5. «Пусто» нельзя сказать поверх файла; ноль врёт не везде одинаково

Правило `set-but-empty = unset` подтверждено: `SERVER_PORT_GRPC=` не перебивает файл; порт остаётся с yaml.

Следствие: **выключить то, что файл включил, пустым env нельзя.**

```
REGISTRY_S3_BUCKET=  +  deploy/config/config.yml
→ bucket: easyp-plugins   # file
```

S3 в основном compose включён файлом. Чтобы выключить — другой файл, не «пустое значение». Для телеметрии в `config.yml` то же: endpoints прописаны; пустой `TELEMETRY_OTEL_EXPORTER_OTLP_ENDPOINT` коллектор не снимает.

Это плата за compose-шаблон `"${VAR:-}"` и за секреты вне git. Для секретов правило верное. Для optional-фич (S3, OTLP) «выключить» невыразимо, если shipped-файл их уже включил.

Нули при этом значат разное:

| Значение | `print` / `validate` | Рантайм |
|---|---|---|
| `cache_max_bytes: 0` | valid, origin file | выключить eviction (**honored**) |
| `max_concurrent_per_ip: 0` | valid | выключить лимит (**honored**) |
| `max_retries: 0` | valid | одна попытка, без ретраев (**honored**) |
| `audit.retention_months: 0` | valid | хранить forever (**honored**) |
| `max_output_size: 0` / `workers: 0` / `burst: 0` | отказ стартовать | — |
| `license.cache_ttl: 0` | valid, print пишет `0s # file` | подменяется на 5m в `license.NewManager` |
| `server.max_recv_msg_size: 0` | valid, print пишет `0` | подменяется на 64MiB в gRPC helper |
| `server.max_concurrent_streams: 0` | valid, print пишет `0` | подменяется на 256 в gRPC helper |
| `audit.pre_create_months: 0` | valid | подменяется на 3 |
| `audit.enqueue_timeout: 0s` / `flush_timeout: 0s` | valid | подменяются на 1s / 5s |
| опустить ключ | дефолт тега | дефолт тега |

Первый блок нулей проверен запуском `validate`/`print`. Второй — запуском `print` (нули видны как file) плюс чтением потребителей; рантайм-подмену до работающего процесса не доводил.

`WORKER_POOL_WORKERS=4` (как дефолт) пропадает из `--changed`, хотя origin — env. «Что я задал» и «что отличается от бинаря» — разные вопросы; флаг отвечает на второй.

Без `config print --origin` отличить «выключил нулём» от «забыл» нельзя. С `--origin` всё равно не видно, что ноль потом отожрут.

### 6. Молча не то, что просили

Не всё падает на старте — и это хуже ошибки.

- **Мусорный `LICENSE_KEY` при валидной длине ключа.** `config validate` зелёный («3 from the environment»). На старте невалидный токен → community, не exit. Написано в `config.enterprise.dev.yml` и в клиенте лицензии; `task tier-dev` существует *потому что* конфиг сам разницу не ловит. Короткий hex (`got 6`) validate уже ловит — проверка длины есть, проверки, что токен *этот* ключ принимает, в validate нет.
- **`worker_pool.workers: 32` в community.** Старт успешен, пул тихо режется до 4 (`cappedWorkers` + лог). Настройка применилась не так. Чтение кода `cmd/easyp-svc/start.go`.
- **`--log_level=debu` (опечатка).** Не падает: warn и **info**, не debug. Дефолт флага при этом **debug** (`service start --help`). Helm ставит `info`. Три разных «нормальных» уровня в зависимости от входа.
- **`cache_max_bytes` без S3.** Комментарий в коде и поведение: eviction не работает, на диске единственная копия. В `config.local.yml` ключа нет — правильно. Если скопировать 2 GiB из dev-файла в local — настройка ничего не сделает.
- **`audit.*` в community.** Поля принимаются, аудита нет. Девять настроек, которые можно «задать».
- **`trusted_proxies: ["10.0.0.1"]` без `/32`.** Здесь как раз громко и понятно (`is not a CIDR`). Редкий случай, когда ошибка учит формату.

Половина TLS, CA без сертификата, отрицательный RPS, пустой DSN — падают на старте, тексты внятные. Это сделано хорошо. Рядом с этим молчаливые режимы выглядят ещё опаснее: оператор привыкает, что «неправильное не стартует», и не проверяет лицензию и опечатки.

`config print` без `--cfg` не вызывает `Validate`: пустой DSN печатается молча. Рецепт Helm «напечатай, что получится» без секрета выглядит как успех.

### 7. Инструменты лучше документации — и отвечают на правильные вопросы

`easyp-svc config print` / `validate` — это и есть продукт для трёх слоёв.

Проверено запуском:

- `--origin` пишет `default` / `file` / `env SERVER_PORT_GRPC` — совпало с реальным приоритетом **env > file > default**.
- `--changed` показывает ровно отличия от бинаря; help прямо говорит, что это «то, что файлу достаточно содержать».
- без `--show-secrets`: DSN и `secret_access_key` → `***`; `access_key_id` и sha256 токенов видны. Разумный компромисс.
- `print` на невалидном конфиге **печатает** и предупреждает `would not start`. `validate` падает. Правильная пара: посмотреть vs поставить шлагбаум.
- без `--cfg` — только env, как думают про Helm. Help это говорит. Сам Helm уже передаёт `--cfg=/etc/easyp/config.yml` (комментарии в коде, что Helm — env-only, устарели).

Их не знает тот, кто читает README или сайт. Знает тот, кто дошёл до шапки yaml или `--help`. Для аудита «поймёт ли посторонний» это провал discoverability, не качества команд.

Helm даже даёт рецепт `helm template … | awk … && config print --origin`. Compose-оператор должен сам догадаться.

## Первая настройка: время и что его съедает

**Не измерил полный `task up`:** локально уже крутились (и падали) контейнеры easyp, на 5432 сидел чужой postgres, SSH к стенду не открылся. Оценка — по документированному пути, наличию Docker/Go/Task и по тому, где путь обрывается.

**До health на счастливом пути: примерно 30–60 минут**, не 5.

Съедает время не «65 настроек», а:

1. **Сборка плагинов** (`task build-plugins`) — несколько Docker-образов, первый раз это основная масса минут.
2. **Выбор входа.** Full stack / minimal local / two-tier / Helm — четыре ритуала, разные файлы, разные порты, разные секреты.
3. **Мёртвые шаги README** (`register-plugins.sh`, устаревший yaml-пример). Легко потратить 15 минут на файл, которого нет.
4. **Расхождение 8080 vs 23410 vs 4443.** Compose прячет gRPC за Traefik на `EASYP_TRAEFIK_TLS_PORT` (4443) и mTLS. Local — plaintext 8080. Человек с README env-блока открывает 8080 и не понимает, почему compose его не слушает.
5. **Если образ старше yaml «только отличия»** — как было локально — старт бесконечно рестартует с `db.driver is required`. Это уже не минуты, это тупик без чтения исходников или `config print` на *том же* бинаре, что в контейнере.

До «я понимаю, с чем живу» — отдельно, и без упоминания `config print` в README это может не случиться никогда.

Двухтировый self-hosted с лицензией, S3 и mTLS объективно не «один docker run». Эта сложность честная. Нарощенная — мёртвые команды, три имени на ключ, дефолты, которые видны только внутри бинаря.

## Три переименовать

1. **`TELEMETRY_OTEL_EXPORTER_OTLP_ENDPOINT` → `TELEMETRY_OTLP_ENDPOINT`**, и/или начать читать стандартный `OTEL_EXPORTER_OTLP_ENDPOINT`. Сейчас имя выглядит как «мы поддерживаем OTel», а стандартное имя игнорируется.
2. **`cache_max_bytes` / `cacheMaxBytes` → что-то с disk/plugins dir** (`plugins_dir_max_bytes`). Имя до сих пор звучит как RAM; это потолок распакованных плагинов на томе. История с «кэш в памяти» не закрыта именем.
3. **Helm `ports.metrics` vs YAML `server.port.metric` vs compose `EASYP_METRICS_PORT`.** Одно слово. Сейчас три, из них одно во множественном числе.

## Три удалить или слить

1. **`db.driver`.** Другого драйвера в коде нет, дефолт всегда postgres, опускание поля роняет старые образы. Это не настройка оператора.
2. **`license.public_key` + `license.public_keys`.** Два способа сказать одно; Helm и compose уже разошлись (map в values vs `LICENSE_PUBLIC_KEYS` в env). Оставить map + один env-формат.
3. **Девять `audit.*` (и `cache_max_bytes` без S3) как «настройки community».** Либо честно не принимать их без лицензии/без bucket, либо в `config print` помечать `inactive`. Сейчас их можно задать и решить, что система пишет аудит.

## Одна вещь, если менять только одну

**Неизвестный ключ YAML (и camelCase вместо snake_case) должен быть ошибкой старта и `config validate`, не warning с exit 0. `config print` должен показывать те же warning.**

Почему не «починить README» и не «свести имена»: при трёх словарях опечатка *будет*. Сейчас загрузчик делает её неотличимой от успеха, а `print --origin` честно показывает дефолт — но до него ещё надо дойти, и он как раз прячет warning. Если опечатка орёт, остальное (слои, only-diffs, даже кривые имена) переживается. Если молчит — оператор всю жизнь думает, что выставил 8888 и 2 GiB.
